What the selected model looks for

Scoring (System 1, contrastive): the text plus a fixed question goes through the frozen Qwen3-8B encoder and a trained state head; each class description goes through a trained action head; the class with the highest scaled cosine wins (softmax over the classes the speaker can receive). The heads are trained with a contrastive loss over the class descriptions: a row's own class is the positive, the other classes are the negatives. Details in docs/architecture.html.

Train a fresh model from your labelled data

Any text classification works: rows of text + label, your own class names and descriptions. The model is a pair of small contrastive heads over a frozen encoder, so a few hundred rows per class is enough and training takes about a minute.

Example use case: the regulatory regime screener, end to end (about 15 minutes)
  1. Train: below, pick the example dataset regime_5way_sample.csv, keep the prefilled classes, validate, train (about a minute).
  2. Read the metrics: accuracy / precision / recall / F1, the confusion matrix, and the linear-probe baseline. Open the full report.
  3. Activate the model, then go to Chat: replay the demo transcripts (or chat live) and flag every verdict you disagree with. Flags are the expert data.
  4. Post-train: on that tab, your flags are listed; add the example regime_5way_expert_corrections.csv as extra SME rows, train a candidate from the active model.
  5. Gate and promote: compare the candidate with the active model on the held-out and OOD sets; promote if nothing regressed. Every model is versioned in the registry (v1, v2, …) with its parent and metrics, and any version can be re-activated.

CSV or JSONL with text and label columns; optional speaker (user / assistant, for conversational data) and split (train / val / test). The model needs one negative class that means "none of the above", with its own examples, or it will assign a class to everything.

Post-train the selected model with expert labels

Continues the selected model's heads on its original training data plus the corrections experts raised in the chat (false-positive / false-negative flags) and, optionally, an uploaded file of expert-labelled rows. The candidate is then gated against the current model on the held-out split (and, for the regulatory example, the OOD sets) before it can be promoted.
