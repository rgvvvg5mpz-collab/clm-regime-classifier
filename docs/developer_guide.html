2. Setup

git clone https://github.com/rgvvvg5mpz-collab/clm-regime-classifier.git
cd clm-regime-classifier
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
git clone https://github.com/Contrastive-LM/CLM.git && .venv/bin/pip install --no-deps -e CLM   # --no-deps: skips vLLM on macOS
.venv/bin/clm-download                                          # reference heads -> ~/.cache/clm/
gh release download v1.1 -p clm_regime_5way.pt -D regime_clf/checkpoints   # 5-way, UI default
gh release download v1.0 -p clm_regime_7way.pt -D regime_clf/checkpoints   # 7-way
# Qwen3-8B (~16 GB) downloads to ~/.cache/huggingface on first use

Label sets. REGIME_LABEL_SET=7way (default) or 5way selects the class list, data directory (data/ vs data_5way/) and checkpoint name for every script in regime_clf/. Checkpoints carry their own class list, so inference.py and the chat UI adapt to whichever file they load.

On a CUDA box you can install CLM with its dependencies (pip install -e CLM), serve the encoder with vLLM, and pass --emb-url http://host:8090/v1/embeddings everywhere instead of loading Qwen3-8B in-process.

5. Gotchas

  • Memory: one Qwen3-8B per 24 GB Mac. Stop the UI server before running evaluate.py, or you'll swap heavily.
  • Embedding cache: regime_clf/emb_cache/store.npy (~200 MB, gitignored) is keyed by the exact state text (message + instruction). Changing INSTRUCTIONS invalidates every entry and costs ~18 min to rebuild on an M5 Pro. Changing CLASSES only re-embeds 7 texts, but needs retraining.
  • Checkpoints carry their own class text: clm_regime_7way.pt stores classes and instructions, and inference.py uses those, not classes.py. That stops a wording edit from silently mismatching a deployed checkpoint.
  • Don't measure similarity on raw encoder embeddings: they are extremely anisotropic (cos ≈ 0.997 between unrelated messages). Use the projected head space, or lexical TF-IDF for deduplication.
  • Python 3.14 works with torch 2.14 / transformers 5.18. vLLM isn't installed on macOS (--no-deps).
  • transformers 5 prints an "UNEXPECTED lm_head.weight" load report for AutoModel. That's expected (we load the base model, not the LM head).
  • Name scrub: tools/name_check.py holds the blocked real-firm names (ROT13-encoded so they never appear in repo text); build_dataset.py replaces them, and the release checklist runs the checker over every file.

6. Improvements, in priority order

P0: correctness and trust

  1. SME adjudication of the OOD sets and the S-ID / S-P boundary. The largest OOD error (S-ID → S-P: 19/45 on the hard set, 12/30 on low/medium) is partly a labelling-convention gap. Have compliance write a one-page decision rule (e.g. "verification bypass or takeover → S-ID even if PII is mentioned") and relabel both training and OOD rows to it.
  2. Decide what “no flag” means in production. The 5-way model deliberately treats privacy and identity-theft content as nothing to flag. If those matters still need a route, pair it with the 7-way model or a dedicated S-P/S-ID detector, and measure the out-of-class false-flag rate (currently 13% on hard, 20% on low/medium S-P/S-ID rows, mostly identity-theft reports read as complaints).
  3. Recall-first thresholds. Production should under-report the negative class: 22/270 OOD violations were predicted compliant by the 7-way model, 25/180 no-flag by the 5-way model. Add a per-class decision rule (flag if 1 − p(compliant) ≥ τ), tune τ on validation for a recall floor (e.g. ≥ 0.95 for 4530 theft and S-ID, mirroring RegModels' recall_floor), and report precision at that operating point.
  4. Calibration. Measure ECE / reliability on validation and fit temperature scaling on logit_scale; the UI shows these probabilities to users.
  5. Automated tests. Add pytest for build_dataset (counts, no conflicts, scrub), inference (golden predictions on ~20 fixed messages), app (FastAPI TestClient with mock_llm, feedback schema), plus a CI job that runs them with a stubbed embedder.

P1: generalization

  1. Train on more varied data, not harder data. The low/medium run showed that explicit rows are no easier for the model (low 73%, medium 80%, hard 77%): it keys on the surface form of the training templates (e.g. a blunt “Buy X, it's right for you” is predicted FINRA 2210 at p = 0.99 because training Reg BI rows are long and hedged). Generate a Fable training set along the three OOD axes at all difficulties (disjoint seed and spec), mix it ~20% with RegModels, and keep both ood_*_v1 sets strictly held out. This is the most likely fix for the 0.977 → ~0.74 gap.
  2. Close the feedback loop. Consume app/data/feedback.jsonl: an SME review queue (RegModels' RLHF_RLAIF_UI is the natural home), then gated retraining that refuses to promote a checkpoint which regresses in-dist test, OOD, or any per-class recall floor.
  3. Multi-label output. Real messages can implicate two regimes (a complaint that also leaks an SSN). Switch the head objective to per-class sigmoid (noul questions) or report every class above a threshold.
  4. Sub-rule routing. After the regime, call the matching RegModels per-track model for the fine label (e.g. d1F_performance_projection), giving an explainable two-stage system.
  5. Ensembling with the probe. On OOD, the probe is at least as good as the heads for both label sets (7-way: 0.747 vs 0.732; 5-way hard: 0.833 vs 0.800; CIs overlap), and their errors may differ. Try averaging probabilities.
  6. Don't expect label-set changes to fix generalization. Dropping S-P/S-ID raised OOD macro-F1 from 0.73 to 0.80–0.83, but the 7-way model collapsed to five classes scores the same. Compare like for like (collapse predictions) before crediting a retrain.

P2: engineering

  1. GPU serving path. Containerise vllm serve Qwen/Qwen3-8B --runner pooling + the FastAPI app; benchmark the advertised CLM latency on CUDA.
  2. Smaller encoder option. The heads are tied to Qwen3-8B. Evaluate the upcoming CLM-35B (quality) and a distilled small encoder (cost) once checkpoints exist.
  3. Multiple seeds and wider grids. Report mean ± sd over 3–5 seeds, and extend the probe grid beyond C = 100.
  4. Context-aware screening. Today each message is scored alone. Include the previous turn in the state (the CLM state can be structured) so that "yes, do it" after a recommendation is caught.
  5. Streaming in the UI, an auth layer for the app, and log rotation for turns.jsonl.

7. Release checklist

  1. Retrain or evaluate; write results to a new dated Tests/<date>_* folder; run Tests/make_reports.py.
  2. Name check: .venv/bin/python tools/name_check.py must report 0 hits.
  3. Bump the release tag; attach clm_regime_7way.pt and its SHA-256; note in-dist and OOD macro-F1 in the release notes.
  4. Update headline numbers in docs/README.html, README.md and CLAUDE.md.
