Methodology

How the data was built, how CLM-8B was adapted, how the model was evaluated, and what the numbers do and don't support.

1. Task definition

Each input is one message from a broker-dealer's GenAI chat channel, written by either the client or the assistant. The output is a single label: the regulation regime the message implicates, or the negative class. Two label sets are trained (regime_clf/classes.py, selected with REGIME_LABEL_SET): 7-way (compliant + six regimes) and 5-way (no_flag + FINRA 2210, Reg BI, FINRA 4530, SEC 17a-3/4). In the 5-way set, Reg S-P and Reg S-ID messages are kept as out-of-class samples labelled no_flag, so the negative class means “nothing among the covered regimes” rather than “nothing at all”. This replaces RegModels' six per-regime binary/multi-label models with one router. It answers which regime applies, not which sub-rule; that finer call stays with the existing per-track models and human review.

The speaker matters. FINRA 2210 and Reg BI judge what the assistant says; FINRA 4530, SEC 17a-3/4, Reg S-P and Reg S-ID judge what the client says. This matches how the RegModels tracks were built (configs/tracks.json, field unit).

2. Data

Source

The six RegModels v2 splits in slm-supervisory-suite/data/ (24,497 rows: train 19,567 / val 2,429 / test 2,501). Every row is synthetic: slot-filled templates plus some LLM augmentation.

Label mapping (regime_clf/build_dataset.py)

  • A row with any violation or complaint label → its track's class (e.g. any d1*/d2/… label in the 2210 track → finra_2210).
  • A row with no labels (each track's negative class: compliant, education_compliant, not_complaint, not_flagged) → the negative class.
  • 5-way only: every row of the regsp and regsid tracks (violation or not) → no_flag; 8,524 negative training rows (43.6%) versus 4,402 (22.5%) in the 7-way set. No reweighting.
  • Multi-label rows (2–3% per track) all fall inside one track, so the regime label is never ambiguous.
  • The original splits are kept, so nothing that was held out in RegModels leaks into training here.
  • Checked: 0 exact duplicate texts across tracks or splits, and 0 texts with conflicting classes.

Scrubbing

33 source rows named a real fund family. Each mention is replaced with the fictional “Harborline” at build time. The RegModels source files themselves are unchanged.

Class balance

compliant 22.5% · finra_2210 21.9% · reg_bi 12.6% · finra_4530 11.0% · sec_17a3_17a4 10.9% · reg_sp 10.6% · reg_sid 10.4% (train). Imbalance is mild, so no reweighting was used. Macro-F1 is the headline metric so that small classes count equally.

3. Model

CLM-8B scores a (state, candidate) pair as exp(logit_scale) · cos(state_head(es), action_head(ec)). Here e is a Qwen3-8B last-token-pooled, L2-normalised embedding, and each head is a 3-layer GELU MLP with LayerNorm (4096 → 1536 → 1536 → 512). A softmax over the candidates gives the class distribution. See Architecture for the diagram.

  • State text: the message, a blank line, then a fixed question (classes.INSTRUCTIONS). This is the layout CLM's schema.state_text expects.
  • Candidates: one plain-English description per class (classes.CLASSES), written from the RegModels label definitions and checked against sample rows.
  • Encoder: CLM's reference stack serves Qwen3-8B through vLLM on CUDA. On Apple Silicon, mps_embedder.py runs Qwen3-8B in-process (bf16, MPS) with the same recipe: raw text, no special tokens, final post-norm hidden state of the last token, L2-normalised.
Encoder parity check. Two worked examples from the CLM model card were reproduced on the local encoder: “What causes tides?” gives 0.9937 for the correct answer (card: 0.993), and the billing/technical routing example gives billing 0.987 (card: 0.939). The rankings match and the confidence differs slightly, which is consistent with bf16-on-MPS vs vLLM numerics.

4. Training

  • Encoder frozen. All encoder embeddings are computed once and cached (text-keyed float16 store, emb_cache/).
  • Both heads and logit_scale are initialised from the published CLM_v0.1-8B.pt and trained with softmax cross-entropy over the 7 candidates. This is the repo's choice --loss softce objective, reimplemented in run_experiment.py so it can train from the cached MPS embeddings.
  • AdamW (weight decay 0.01), one-cycle LR, batch 256, 30 epochs. The checkpoint kept is the epoch with the best validation macro-F1.
  • Learning-rate sweep {1e-4, 3e-4, 1e-3}, selected on validation only. 7-way: 1e-3 won (val 0.9769, epoch 28); the first 15-epoch run at 1e-4 was undertrained (test 0.877). 5-way: same sweep, 1e-3 won again (val 0.984, epoch 28). The state question is identical for both sets, so the cached encoder embeddings are shared; only the candidate texts differ.
  • Seed 20933. On one M5 Pro, embedding takes ~18 min (24.5k texts), and training takes ~2 min per configuration.

5. Baselines

  • Zero-shot CLM: the published heads, unchanged. Three candidate wordings × heads/raw-encoder space × with/without a label-free prior correction were tried (zero_shot_variants.py). The best macro-F1 was 0.236. With its default wording, the model sends nearly every message to reg_bi. The conclusion is that CLM-8B's zero-shot ability doesn't extend to this regulatory taxonomy, and it has to be fine-tuned.
  • Linear probe: multinomial logistic regression on the same frozen Qwen3-8B state embeddings. C was chosen on validation from {1, 10, 100}; 100 won, which is at the edge of the grid. This measures how much the CLM heads add beyond the encoder.

6. Evaluation protocol

  • In-distribution: the RegModels v2 test split. It is never used for training or model selection.
  • Out-of-distribution hard set: 315 messages written by Claude Fable 5.1, run as three independent agents with one OOD axis each (105 messages per agent, 15 per class):
    • register_shift: SMS fragments, voice-to-text, non-native English, legal-letter tone, buried signals, bullet/table answers;
    • adversarial_confuser: compliant text full of trigger vocabulary; boundary cases where one regime dominates; negation, hypotheticals, sarcasm, quoted speech;
    • novel_scenario: tokenized ETPs, structured notes, annuities, 529/HSA, trusts and POAs, estates, expats, AI-specific failures.
    Every row carries a one-sentence rationale that names the nearest competing class. The generation spec is regime_clf/ood/SPEC.md.
  • Out-of-distribution low/medium set: 210 further messages from two more Fable agents, one per difficulty (105 each, 15 per class, spread evenly over the same three axes). Low means the regime is stated almost outright with no competing regime; medium means the signal is clear but implicit (a grievance without the word “complaint”, PII given in passing). Definitions are in SPEC.md. The purpose is to separate distribution shift from inferential difficulty.
  • OOD integrity checks (ood/build_ood.py): schema, label/speaker consistency, no real firm names, no exact matches with any split, and near-duplicates against train via character 3–5-gram TF-IDF cosine (threshold 0.80). Result: 0 rows dropped from either set; median nearest-train similarity 0.30 (hard) and 0.28 (low/medium); no overlap between the two OOD sets.
  • Evaluating the 5-way model on the OOD sets: labels outside its set (reg_sp, reg_sid) are mapped to no_flag, so those rows test whether the model stays silent on out-of-class content; evaluate.py also reports accuracy by source label. For a like-for-like comparison the 7-way model's predictions are collapsed the same way.
  • Speaker masking: optionally restricts the softmax to the classes valid for the speaker. In-distribution it changes nothing, because the model already never crosses speakers. On OOD it adds +0.004 macro-F1.
  • Uncertainty: 95% percentile bootstrap (1,000 resamples) for accuracy and macro-F1.

7. Findings

  1. Fine-tuned CLM heads are the best in-distribution model: 0.977 [0.970, 0.983] vs probe 0.955 [0.946, 0.964]. The intervals don't overlap.
  2. Generalization is the real limit: OOD macro-F1 is 0.732 [0.680, 0.778]. The probe scores 0.747 [0.697, 0.790], and the intervals overlap, so neither is significantly better on new text. Very-hard items score 68% vs 77% for hard ones.
  3. Error structure on OOD: Reg S-ID → Reg S-P (19/45 S-ID rows); Reg BI → FINRA 2210 (14/45); violations predicted compliant (22/270, mostly S-P, 17a-3/4 and BI). FINRA 4530 holds up best (F1 0.91).
  4. Part of the S-ID/S-P gap is a labelling convention. One Fable agent noted that the training data labels some identity-verification situations (e.g. an elderly parent handing a verification code to a caller) as Reg S-P, whereas the OOD set treats verification bypass and takeover as Reg S-ID. A compliance SME needs to settle that boundary before anyone retrains.
  5. Difficulty is not what drives the OOD drop. On the low/medium set the fine-tuned heads score 0.748 [0.688, 0.801]: low rows 73.3%, medium 80.0%, versus hard 76.9% and very hard 68.0%. Rows that state the regime outright are no easier for the model than rows that require inference. The same two confusions dominate, at high confidence: Reg S-ID → S-P or 4530 (23 of 30 S-ID rows wrong), and short direct Reg BI recommendations → FINRA 2210 (7 of 30; e.g. “Buy the Copperleaf Dividend Fund. For your situation, it's the right call.” at p = 0.99). Training Reg BI rows are long and hedged, so the model learned the template style rather than the concept. The probe shows the same pattern (low 69.5%, medium 78.1%).
  6. 5-way retraining: better numbers, same model. The 5-way heads score 0.983 in-distribution, 0.800 OOD hard and 0.830 OOD low/medium. But the 7-way model collapsed to the same five classes scores 0.985 / 0.822 / 0.839, so the OOD improvement is from no longer scoring Reg S-P and Reg S-ID (the two weakest classes), not from the new training. The Reg BI → FINRA 2210 confusion is unchanged (16/45 hard, 9/30 low/medium). Out-of-class handling is decent but not clean: of the S-P/S-ID rows, 87% (hard) and 80% (low/medium) are correctly left unflagged; the false flags are identity-theft reports read as FINRA 4530 complaints or 17a-3/4 records events. The linear probe is again as good as or better than the heads on OOD (0.833 vs 0.800 on hard).
  7. Zero-shot doesn't work for this taxonomy (macro-F1 ≤ 0.24 across all variants).
  8. Embedding geometry: because every state ends with the same instruction, raw last-token embeddings of different messages sit at cosine ≈ 0.997. They can't be used for similarity or deduplication without the heads.

8. Limitations and threats to validity

  • Both train and test data are synthetic. The OOD sets are also synthetic, from a different generator, so they measure robustness to style and scenario shift, not to real client traffic.
  • OOD labels are Fable's, and only spot-checked, not SME-adjudicated. Some disagreement with the training labels reflects convention rather than model error (finding 4).
  • Single label per message. Real messages can implicate two regimes; the OOD set deliberately excluded genuinely co-equal cases.
  • In the 5-way set, treating identity theft and privacy content as “no flag” is a modelling convenience for a model that doesn't cover those rules; in deployment those messages still need a route (the 7-way model, or a separate detector).
  • One seed, one hardware platform. Reported latency is for an Apple M5 Pro; CUDA + vLLM will differ.
  • The probe's C is at the edge of its grid, so the baseline may be slightly underestimated.

9. Reproducing

cd regime_clf
../.venv/bin/python build_dataset.py                          # data/   (REGIME_LABEL_SET=5way -> data_5way/)
../.venv/bin/python run_experiment.py --epochs 30 --lr 1e-3 --out ../Tests/<date>_in_distribution/sweep/lr_1e-3
./sweep.sh ../Tests/<date>_in_distribution/sweep               # full LR sweep
../.venv/bin/python evaluate.py --data data/test.jsonl --out ../Tests/<date>_in_distribution/eval_test
../.venv/bin/python ood/build_ood.py
../.venv/bin/python evaluate.py --data ood/ood_hard_v1.jsonl --out ../Tests/<date>_ood_fable_hard
../.venv/bin/python ood/build_ood.py --parts raw_low.jsonl raw_medium.jsonl --out ood_low_medium_v1.jsonl
../.venv/bin/python evaluate.py --data ood/ood_low_medium_v1.jsonl --out ../Tests/<date>_ood_fable_low_medium
../.venv/bin/python zero_shot_variants.py ../Tests/<date>_in_distribution/zero_shot_variants.json
# 5-way variant: prefix every command with REGIME_LABEL_SET=5way, e.g.
REGIME_LABEL_SET=5way ./sweep.sh ../Tests/<date>_5way_in_distribution/sweep
REGIME_LABEL_SET=5way ../.venv/bin/python evaluate.py --data ood/ood_hard_v1.jsonl --out ../Tests/<date>_5way_ood_fable_hard
cd .. && .venv/bin/python Tests/make_reports.py
