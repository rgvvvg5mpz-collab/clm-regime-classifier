Cost and latency: prompt-based LLM judges vs a trained CLM classifier

Worked example: the 5-class regulatory screener (one decision per chat message)
CLASP · estimates as of 2026-10-10
Volume scenario: 1,000,000 classifications / day

At this volume, the trained CLM costs about $1.2K a month on 2 rented GPUs. A prompt-based judge costs $5.2K to $225.6K a month, depending on the model. The CLM answers in 80 ms, while the judges take 566 ms to 4.6 s. The CLM runs one encoder pass and generates nothing, so its cost does not depend on prompt length or reasoning tokens.

How the numbers are built

  • Judge input is 780 tokens: about 250 for instructions, 348 for the 7 class definitions (measured), plus a 50-token message (measured mean 45 in test, 54 out of distribution).
  • Judge output is a 20-token JSON label. The reasoning models also pay for thinking tokens at the output price, and Opus 5.5 always thinks.
  • Judge latency is time to first token plus output tokens divided by the published speed. Benchmarks on long reasoning tasks are far slower, so treat them as an upper bound.
  • CLM cost assumes 2 always-on 24 GB L4-class GPUs at $0.80/h. Each handles 20 msg/s against an average load of 11.6 msg/s with 2.5× peak headroom. At full utilisation the cost falls to $11 per 1M.

What moves the result

  • Prompt size. Adding few-shot examples to reach 2,000 input tokens raises every judge's cost by about 2.5×. Prompt caching only helps prefixes above the provider's minimum cacheable length.
  • Batch APIs from Anthropic and Google halve the price, but only for offline jobs that can wait hours.
  • Low volume favours the judges. Below about 226K classifications a day, the rented GPUs cost more than the Llama judge. A CLM on hardware you already own costs only the electricity.
  • Provider spread. Llama 4 Maverick input prices range from $0.15 to $0.50 per 1M tokens, and speed ranges from 12 to 272 tokens/s.

Not in the per-call figures

  • Accuracy. The CLM's quality is measured. None of the judges have been evaluated on this task yet. The next step is to run them on the same test and out-of-distribution files.
  • CLM one-off costs. These are labelled data and a few minutes of head training on cached embeddings. Embedding the training set takes minutes to hours.
  • Judge one-off costs. These are prompt engineering and a labelled set to validate the prompt against.
  • Data control. The CLM keeps messages in-house. The hosted judges send every message to a third party.
