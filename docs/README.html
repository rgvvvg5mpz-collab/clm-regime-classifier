CLM Regime Classifier

A classifier that reads a message from a broker-dealer's GenAI chat channel and names the securities-regulation regime it implicates, or flags nothing. Two label sets are trained: the original 7-way model and a 5-way model that drops Reg S-P and Reg S-ID and treats their messages as out-of-class “no flag” samples. It is built on CLM-8B, the contrastive language model from Stanford and NVIDIA (Sept 2026), and is trained on the six RegModels datasets.

The classes

The 5-way model (clm_regime_5way.pt, the chat UI's default) uses no_flag plus the first four regimes below; Reg S-P and Reg S-ID messages are out-of-class samples that belong to no_flag. The 7-way model (clm_regime_7way.pt) uses compliant plus all six. Select with REGIME_LABEL_SET=5way|7way.

LabelRegimeSpeaker it applies to
no_flag / compliantNothing to flag (5-way: including privacy and identity-theft content)either
finra_2210FINRA Rule 2210: communications with the public (misleading, promissory, unbalanced, projections, missing disclosures)assistant
reg_biRegulation Best Interest: personalized recommendation or proprietary steeringassistant
finra_4530FINRA Rule 4530: reportable written customer complaintclient
sec_17a3_17a4SEC Rules 17a-3/17a-4: off-channel communication, record evasion, records updatesclient
reg_spRegulation S-P: sensitive personal data, privacy requests, data incidents (7-way only)client
reg_sidRegulation S-ID: identity-theft red flags, account-takeover signals (7-way only)client

The 5-way OOD numbers are higher mainly because the two hardest regimes are no longer scored: the 7-way model's own predictions collapsed to the same five classes do as well (third row). On the out-of-class rows the 5-way model correctly stays silent 87% (hard) / 80% (low/medium) of the time; the false flags are mostly identity-theft reports read as complaints.

Use the OOD numbers for planning. The training data is synthetic and templated. On Fable-written messages in new styles and scenarios, accuracy falls from 97.9% to about 75%, and that holds even when the regime is stated almost outright (low-difficulty rows: 73.3%). The weak spots are Reg S-ID (7-way: read as Reg S-P or a complaint; 5-way: sometimes flagged as a complaint instead of left alone) and blunt Reg BI recommendations (read as FINRA 2210 by both models). See the test runs.

Quick start

# 1. environment (Python 3.12+; tested on 3.14, macOS / Apple Silicon)
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
git clone https://github.com/Contrastive-LM/CLM.git && .venv/bin/pip install --no-deps -e CLM

# 2. weights: Qwen3-8B (~16 GB, auto-downloads on first use), reference CLM heads, our fine-tuned heads
.venv/bin/clm-download
gh release download v1.1 -p clm_regime_5way.pt -D regime_clf/checkpoints   # 5-way (UI default)
gh release download v1.0 -p clm_regime_7way.pt -D regime_clf/checkpoints   # 7-way

# 3. classify
cd regime_clf
../.venv/bin/python inference.py "Can you text me on my personal cell instead?" --unit client_message

# 4. chat UI with screening
cd .. && .venv/bin/python -m uvicorn app.server:app --port 8710   # open http://localhost:8710

Provenance

  • CLM-8B: Contrastive-LM/CLM-v0.1-8B, code Contrastive-LM/CLM (Apache 2.0). Base encoder Qwen/Qwen3-8B (Apache 2.0).
  • Training data: RegModels slm-supervisory-suite/data v2 splits (synthetic). One real fund-family name is replaced with a fictional one (“Harborline”) at build time.
  • OOD sets: written by Claude Fable 5.1 to regime_clf/ood/SPEC.md (hard/very-hard: 315 rows; low/medium: 210 rows), then checked against the training data for duplicates and near-duplicates.
