CLASP: Contrastive Labelling And System-1 Prediction

CLASP is a workbench for building System-1 text classifiers with a contrastive loss: two small heads (CLM-8B, Stanford/NVIDIA) trained over a frozen Qwen3-8B encoder, so a few hundred labelled rows per class train a model in about a minute. The browser UI covers the whole loop: 0 curate data with Claude Code, 1 train, 2 use the model to screen conversations and flag its mistakes, 3 fold the flags back in as a gated, versioned new model.

The repo ships one worked example, a regulatory regime screener for a broker-dealer's GenAI chat (FINRA 2210, Reg BI, FINRA 4530, SEC 17a-3/4, Reg S-P, Reg S-ID), trained on the six RegModels datasets. The numbers below are that example's.

The classes

The 5-way model (clm_regime_5way.pt, the chat UI's default) uses no_flag plus the first four regimes below; Reg S-P and Reg S-ID messages are out-of-class samples that belong to no_flag. The 7-way model (clm_regime_7way.pt) uses compliant plus all six. Select with REGIME_LABEL_SET=5way|7way.

LabelRegimeSpeaker it applies to
no_flag / compliantNothing to flag (5-way: including privacy and identity-theft content)either
finra_2210FINRA Rule 2210: communications with the public (misleading, promissory, unbalanced, projections, missing disclosures)assistant
reg_biRegulation Best Interest: personalized recommendation or proprietary steeringassistant
finra_4530FINRA Rule 4530: reportable written customer complaintclient
sec_17a3_17a4SEC Rules 17a-3/17a-4: off-channel communication, record evasion, records updatesclient
reg_spRegulation S-P: sensitive personal data, privacy requests, data incidents (7-way only)client

Accuracy and macro-averaged precision / recall for every run, plus per-class tables, are in Tests/METRICS.md (regenerated with the reports). The 5-way OOD numbers are higher mainly because the two hardest regimes are no longer scored: the 7-way model's own predictions collapsed to the same five classes do as well (third row). On the out-of-class rows the 5-way model correctly stays silent 87% (hard) / 80% (low/medium) of the time; the false flags are mostly identity-theft reports read as complaints.

Use the OOD numbers for planning. The training data is synthetic and templated. On Fable-written messages in new styles and scenarios, accuracy falls from 97.9% to about 75%, and that holds even when the regime is stated almost outright (low-difficulty rows: 73.3%). The weak spots are Reg S-ID (7-way: read as Reg S-P or a complaint; 5-way: sometimes flagged as a complaint instead of left alone) and blunt Reg BI recommendations (read as FINRA 2210 by both models). Quick start

git clone https://github.com/rgvvvg5mpz-collab/clm-regime-classifier.git && cd clm-regime-classifier
scripts/run_ui.sh          # first run sets up .venv, CLM and the shipped models, then serves http://localhost:8710

Or open the clone in Claude Code and ask it to run the UI: the repo ships a run-ui skill and launch configurations for that. scripts/setup.sh does the setup on its own (idempotent); the Qwen3-8B encoder (~16 GB) downloads on first use. Needs Python 3.10+, ~20 GB of disk, and Apple Silicon with 24 GB+ or a CUDA GPU with 24 GB+.

From code, outside the UI:

.venv/bin/python -m engine.classifier --checkpoint models/clm_regime_5way.pt "Can you text me on my personal cell instead?" --unit client_message

Provenance

  • CLM-8B: Contrastive-LM/CLM-v0.1-8B, code Contrastive-LM/CLM (Apache 2.0). Base encoder Qwen/Qwen3-8B (Apache 2.0).
  • Training data: RegModels slm-supervisory-suite/data v2 splits (synthetic). One real fund-family name is replaced with a fictional one (“Harborline”) at build time.
  • OOD sets: written by Claude Fable 5.1 to examples/regulatory/ood/SPEC.md (hard/very-hard: 315 rows; low/medium: 210 rows), then checked against the training data for duplicates and near-duplicates.
